## 1. 一代落地复盘（问题清单）

一代 `1.0.0.001` 已完成「工程脚手架 + 应用列表 + 详情 + 单个/批量卸载 + 实时刷新」并通过编译签名验证。站在真实使用视角，二代必须解决一代遗留的六个问题：

| # | 一代现状 | 用户视角的痛点 | 二代对应措施 |
|---|---|---|---|
| 1 | 只有 APK 体积（`PackageInfo.length`） | 「这个应用到底占了多少空间、为什么这么大」看不到，缓存/数据/资源占比是黑盒 | 接入 `StorageStatsManager`，拆分 APK / 数据 / 缓存 / AOT / 引导配置档 |
| 2 | 没有任何「用得多不多」的信息 | 装了一堆半年没打开的应用，列表里看不出来 | 接入 `UsageStatsManager`（使用时长 / 启动次数 / 最后使用时间） |
| 3 | 卸载只能逐个确认弹窗 | 清理 30 个应用要点 30 次 | 批量治理队列 + 风险分级 + 批量操作审计日志 |
| 4 | 系统应用不可操作（置灰） | 预装臃肿应用是清理-storage 的主要障碍 | Shizuku 免 root 接入：针对当前用户卸载 / 恢复 / 隐藏 / 强制停止 |
| 5 | 无备份能力 | 卸载前无法导出 APK，重装需重新找源 | 多 APK split 打包导出 + 备份清单 + 一键还原 |
| 6 | 无任何「体检」 | 危险权限应用、长期不用应用无人提示 | 权限风险扫描 + 闲置识别 + 相似冗余应用检测 |

**一代技术债（需在二代偿还）**

- 无持久层：所有状态在内存，进程被杀即丢；备份清单、体检缓存无处安放 → 引入 Room。
- 无设置持久化：设置页选项未落盘（当前依赖 DataStore 的最小实现需在二代补齐）。
- 权限引导缺失：一代仅在设置页展示说明，未做「分层解锁 + 状态自检」。
- `AppRepository` 广播监听为进程级注册，冷启动不重放，退出再进需靠手动刷新兜底 → 二代改为 `StateFlow` + 首帧主动同步。

## 2. 二代产品定位

**一句话定位**：从「能看能卸的列表工具」升级为「设备应用治理中枢」——看得清占用、看得懂行为、看得动系统、可救回来。

**目标用户**

| 画像 | 核心诉求 | 二代对应能力 |
|---|---|---|
| 空间焦虑型（128G 机型用户） | 找出并清掉占空间的僵尸应用 | 存储可视化 + 大小排序 + 闲置标记 + 一键清理建议 |
| 洁癖整理型 | 清预装、去重、隐私收敛 | Shizuku 系统应用治理 + 相似应用检测 + 权限风险扫描 |
| 效率管理型 | 知道自己时间花在哪个 App | 使用统计 + 启动次数排序 + 使用时长排行 |
| 保守惜命型 | 怕误删，想留退路 | 全量操作日志 + APK 备份 + 还原记录 |

**与同类的差异点（二代护城河）**

1. **可恢复的系统应用治理**：免 root 下的「针对当前用户卸载」，配合隐藏与还原，区别于只能禁用。
2. **卸载即备份**：批量清理前自动打包 split APK，形成可还原清单。
3. **风险分级而非一刀切**：借鉴 Canta / UAD 的分级思路（推荐 / 高级 / 关键 / 系统），把「能不能删」交给知识库与用户判断，而不是替用户决定。
4. **完全离线**：不申请网络权限，全部数据本地处理。

## 3. 功能模块（二代共 8 个）

### M1 存储空间可视化【P0】

**目标**：回答「空间去哪了」。

- 应用详情页新增存储分项：APK、数据、缓存、外部数据、AOT 编译产物、引导配置档。
- 应用列表支持按「占用大小」排序，顶部汇总「用户应用合计 / 系统应用合计 / 缓存合计」。
- 全局存储页：卷总容量、已用、可用；横向柱状图按类别分段。
- Android 15（API 35）启用 `StorageStats.getAppBytesByDataType()` 做更细拆分，低版本自动降级为 `appBytes / dataBytes / cacheBytes` 三项。

**交互要点**

```
应用详情 → [存储] 区块
┌──────────────────────────────┐
│ 总占用 1.24 GB               │
│ ████████████████░░░░░░  68%   │
│ APK      412 MB  ████████     │
│ 数据      520 MB  ████████     │
│ 缓存      246 MB  ████         │
│ AOT        58 MB  █           │
│ 配置档      4 MB  ·            │
└──────────────────────────────┘
```

**技术要点**

- `StorageStatsManager.queryStatsForPackage(storageUuid, packageName, Process.myUserHandle())`，仅需 `QUERY_ALL_PACKAGES`，无需 root。
- `storageUuid` 取 `applicationInfo.storageUuid`，需 `StorageManager` 的 `UUID_DEFAULT` 回退。
- 统计查询是 Binder 调用，**必须**在 IO 线程批量化（一次查询缓存 60s，按 uid+版本号做 key）。
- Android 15 新增：`APP_DATA_TYPE_FILE_TYPE_APK / DEXOPT_ARTIFACT / REFERENCE_PROFILE / CURRENT_PROFILE / DM / ...`，按需选择暴露，避免过度细分。

**验收标准**

- 200 个应用的存储统计 60 秒缓存内完成，无主线程卡顿（`Choreographer` 掉帧 < 5%）。
- 与系统设置「存储-应用用量」的总量误差 ≤ 2%（同一时刻同一应用）。

### M2 应用使用统计【P0】

**目标**：回答「哪些该卸」。

- 采集：最后使用时间、前台总时长（毫秒精度需权限）、启动次数。
- 列表支持「按最后使用时间」「按使用时长」「按启动次数」排序，未采集到数据显示为「无数据」而非 0，避免误判。
- 闲置识别：连续 30 天未启动 → 列表打「闲置」标签，筛选器可一键筛出。
- 排行页：本周/本月使用时长 Top 20、启动次数 Top 20。

**技术要点**

- 特殊权限 `PACKAGE_USAGE_STATS`（`android.permission.PACKAGE_USAGE_STATS`，通过 `Settings.ACTION_USAGE_ACCESS_SETTINGS` 授予，非运行时弹窗）。
- 查询入口：`UsageStatsManager.queryUsageStats()` / `queryEvents()`；事件类型 `ACTIVITY_RESUMED` 推算启动次数。
- **降级策略**：未授权时功能区显示引导卡片而非空白页，列表排序项自动禁用并说明原因。
- 精确时间戳需 `PACKAGE_USAGE_STATS` + 用户已授权；无权限时仅能取到粗粒度（部分 ROM 不返回）。

**验收标准**

- 授权后 5 秒内出排行；未授权时功能整体隐藏而非报错。
- 启动次数与系统设置数字基本一致（误差来自厂商 ROM 统计差异，属预期）。

### M3 批量治理中心【P0】

**目标**：把「逐个点」变成「有序批」。

- 多选能力增强：按筛选结果全选、按分类批量选择（如「全部闲置且 >200MB」）。
- 批量动作：卸载、清理缓存（Shizuku/普通权限分层）、导出备份、加入待清理清单。
- 风险分级（借鉴 Canta / UAD 的成熟范式）：

| 级别 | 含义 | 二代处理 |
|---|---|---|
| 推荐 | 明显冗余，卸载无副作用 | 一键批量卸载，默认选中 |
| 高级 | 需谨慎，删除后可能影响功能（如厂商服务） | 逐个确认，展示依赖提示 |
| 关键 | 卸载可能导致桌面/电话/系统服务异常 | 默认禁止，仅折叠在「高级模式」开关后 |
| 系统 | 分区系统应用，需 Shizuku/L5 权限 | 显示可用操作（隐藏/停用/针对当前用户卸载） |

- 操作审计日志：每次批量操作写 Room（时间、包名、动作、结果），提供「撤销本次批量卸载」（依赖备份还原或 `install-existing`）。

**验收标准**

- 批量 50 个应用的卸载流程不 ANR，进度可视、可中断、可继续。
- 每条日志可回溯；「撤销」能恢复被移除的当前用户应用（前提：APK 仍在分区）。

---

### M4 系统应用深度管理（Shizuku）【P0 · 差异化】

**目标**：在**不 root** 的前提下把系统应用真正管起来。

- 免 root 提权：Shizuku 13.6.0（支持 Android 15 / Android 16 QPR1）通过无线调试启动。
- 依赖库：`dev.rikka.tools.shizuku:api` + `dev.rikka.tools.shizuku:provider`；宿主需实现 `ShizukuProvider`。
- 能力映射：

| 能力 | 普通权限 | Shizuku 路径 |
|---|---|---|
| 停用 / 启用应用 | `setComponentEnabledSetting`（可停用整个应用包） | 相同，但可覆盖更多厂商限制项 |
| 隐藏图标 | `setComponentEnabledSetting(DISABLED_USER)` | `pm hide` 系列命令（部分 ROM） |
| 强制停止 | `forceStopPackage` | 同权限（Shizuku 下更稳定） |
| 清除数据 | 有风险/部分 ROM 限制 | `pm clear` |
| 针对当前用户卸载系统应用 | **不可用** | `pm uninstall -k --user 0 <pkg>` |
| 还原系统应用 | **不可用** | `cmd package install-existing <pkg>` |

- 连接状态可视化：未安装 Shizuku / 未运行 / 未授权 三态明确提示，提供跳转 Shizuku 与「无线调试启动」图文引导。
- **安全边界（硬约束）**：
  - 一律使用 `--user 0`（当前用户），**不触碰系统分区**，保证 OTA 可正常更新、保修不受影响。
  - 「关键」级系统应用（SystemUI / 电话 / 桌面 / 输入法）永不提供卸载入口。
  - 所有 Shizuku 操作写入审计日志，提供「全部还原」按钮（批量 `install-existing`）。

**验收标准**

- Android 11/13/14/15 各一台真机：无线调试配对 → Shizuku 授权 → 卸载臃肿应用 → 还原，全部成功。
- Shizuku 未运行时，系统应用区所有按钮禁用并给引导，不出现崩溃或静默失败。

### M5 APK 提取与备份【P1】

**目标**：卸载前留退路。

- 导出模式二选一：`base.apk` 快速导出（单 APK）/ 完整 split 集合（`apks/*.apk` + `toc.pb` 结构，可直接安装）。
- 导出目标：应用私有目录 / 外部存储 `Documents` / 系统分享面板。
- 备份清单入库：记录包名、版本号、versionCode、导出时间、文件路径、哈希（SHA-256）。
- 还原：从清单调起安装 Intent（`ACTION_VIEW` + FileProvider）；split 集合需按目录整体传递。
- 体积与性能：大包导出在后台 `WorkManager` 执行，通知栏显示进度；单个应用导出上限 4GB（防空间耗尽）。

**技术要点**

- `packageManager.getPackageArchiveInfo` 无法拿全部分片；分片清单从 `ApplicationInfo.splitSourceDirs` + `splitNames` 读取。
- FileProvider + `FLAG_GRANT_READ_URI_PERMISSION` 传递，禁止明文 `file://`。
- 已签名 APK 重打包后无法覆盖安装（签名不一致），文档明确说明：备份用于「重装到无此应用的环境」，不保证原位覆盖。

### M6 应用体检中心【P1】

**目标**：主动发现风险与冗余。

| 检查项 | 判定逻辑 | 建议动作 |
|---|---|---|
| 危险权限过多 | 申请 ≥ 5 项危险权限 | 详情页逐项复核，提供跳转系统权限页 |
| 长期闲置 | 30 天未启动 且 占用 > 100MB | 加入待清理清单 |
| 相似冗余 | 同类别/同开发者 多实例（如两个日历） | 提示保留其一 |
| 大缓存 | 缓存 > 2× 应用本体 | 建议清理缓存 |
| 后台自启 | 声明开机启动/自启且长期不用 | 建议停用（Shizuku 分层） |
| 通知轰炸 | 近 7 天通知数 > 阈值 | 建议关闭通知 |

- 体检报告页：评分（0–100）+ 分级问题列表 + 「一键处理可自动处理项」。
- 结果缓存 Room，7 天有效期；后台体检走 `WorkManager` 周期任务（每天一次）。

**注意**：`UsageStatsManager.queryEvents()` 需 `PACKAGE_USAGE_STATS`，通知统计需 `NotificationListenerService`（绑定需用户手动授权，**不申请**——二代仅在用户手动开启时提供通知统计，不做静默监听）。

## 4. 权限与合规模型（二代升级版）

### 4.1 权限分层（延续一代 L0–L5 并细化）

| 层级 | 权限/能力 | 触发方式 | 缺失时的产品行为 |
|---|---|---|---|
| L0 | 无（启动即用） | — | 列表可用，仅显示基础信息 |
| L1 | `QUERY_ALL_PACKAGES` | 普通权限，安装即授 | 全量列表；未授则只显示可见范围并提示 |
| L2 | `REQUEST_DELETE_PACKAGES` | 普通权限 | 卸载按钮禁用并说明 |
| L3 | `PACKAGE_USAGE_STATS` | 特殊权限，设置页跳转 | 使用统计区整体隐藏（不显示 0） |
| L4 | Shizuku（`moe.shizuku.manager.permission.API_V23`） | 运行时，Shizuku 应用内授权 | 系统应用操作按钮禁用 + 三态引导 |
| L5 | Root | 不提供 | 二代**不内置**任何 root 能力 |

### 4.2 隐私承诺（写入应用内与商店页）

- **不申请网络权限**（Manifest 无 `INTERNET`），无法上传任何数据。
- 不接入任何统计/广告 SDK。
- 备份文件与体检数据仅存本机；卸载应用即彻底删除（Room 级联清理）。
- 通知统计需用户显式绑定 `NotificationListenerService`，默认关闭，且可见可撤销。

### 4.3 分发合规

- `QUERY_ALL_PACKAGES` 受 Google Play 政策限制 → **主渠道为 GitHub Releases + F-Droid**，不在 Play 上架。
- 申请 Play 时可按「设备管理类 / 文件管理」资质走审核，或改用 `<queries>` 白名单方式（代价：无法枚举全量应用）。
- 开源协议：MIT；版权与来源声明在 README 与设置页「关于」中展示。

## 5. 技术架构升级

### 5.1 架构分层

```
com.yunlu.kongjian
├── core/
│   ├── model/          数据模型（含 V2 新增 StorageUsage / UsageStat / RiskLevel）
│   ├── util/           格式化、时间、单位换算
│   └── permission/     权限状态机（单一真源，UI 只读订阅）
├── data/
│   ├── source/         PackageManager / UsageStats / StorageStats / Shizuku 四个数据源
│   ├── repo/           聚合仓库 + 缓存策略（内存 LRU + Room 落库）
│   ├── db/             Room：备份清单 / 审计日志 / 体检缓存 / 使用统计快照
│   └── prefs/          DataStore：所有设置项
├── feature/
│   ├── applist/  detail/  storage/  usage/  bulk/
│   ├── systemapps/      Shizuku 治理（含三态引导）
│   ├── backup/  health/  settings/  widget/
├── shizuku/            ShizukuProvider、命令封装、还原批处理
└── work/               WorkManager：后台体检、批量导出
```

### 5.2 关键技术选型变更

| 维度 | 一代 | 二代 | 理由 |
|---|---|---|---|
| 持久化 | 无 | **Room 2.6** | 备份清单、审计日志、体检缓存需要可查询 |
| 设置 | 最小实现 | **DataStore Preferences** | 替代 SharedPreferences，协程安全 |
| 任务调度 | 无 | **WorkManager 2.9** | 后台体检、大包导出 |
| 列表性能 | 全量 `LazyColumn` | **分页 + 稳定 key + 图标 LRU 缓存** | 300+ 应用滚动 60fps |
| 状态流 | `StateFlow` + `combine` | 沿用 + **状态机化权限** | 避免权限状态在各页重复判断 |
| 提权 | 无 | **Shizuku API** | 免 root 系统应用治理 |
| 测试 | 无 | 单测（统计换算、风险分级）+ UI 冒烟 | 核心逻辑可回归 |

### 5.3 关键实现清单（代码级）

**存储统计（分项）**

```kotlin
suspend fun queryAppStorage(pkg: String): StorageUsage = withContext(Dispatchers.IO) {
    val ssm = context.getSystemService(StorageStatsManager::class.java)
    val uuid = context.getSystemService(StorageManager::class.java)
        .getUuidForPath(context.filesDir)          // 关键：需真实路径拿卷 UUID
    val stats = ssm.queryStatsForPackage(uuid, pkg, Process.myUserHandle())
    StorageUsage(
        appBytes = stats.appBytes,
        dataBytes = stats.dataBytes,
        cacheBytes = stats.cacheBytes,
        externalDataBytes = stats.externalDataBytes,
        aotBytes = if (Build.VERSION.SDK_INT >= 35) {
            stats.getAppBytesByDataType(StorageStatsManager.APK_DATA_TYPE_FILE_TYPE_DEXOPT_ARTIFACT)
        } else null,                                // 低版本降级为 null，UI 不展示该行
    )
}
```

**使用统计（闲置判定）**

```kotlin
val cutoff = System.currentTimeMillis() - 30L * 24 * 3600 * 1000
val idle = lastUsedElapsedRealtime == 0L ||
           SystemClock.elapsedRealtime() - lastUsedElapsedRealtime > IDLE_THRESHOLD_MS
// 注意：无权限时 API 返回空列表 → 显示"无数据"，禁止兜底为 0（会误判为闲置）
```

**停用 / 启用应用（无需 Shizuku 即可用）**

```kotlin
val state = if (enabled) PackageManager.COMPONENT_ENABLED_STATE_ENABLED
            else PackageManager.COMPONENT_ENABLED_STATE_DISABLED_USER
pm.setComponentEnabledSetting(
    ComponentName(pkg, pkg), state, PackageManager.DONT_KILL_APP
)
```

**Shizuku 侧：针对当前用户卸载 + 还原（可恢复）**

```kotlin
// 卸载（仅当前用户，系统分区不动，OTA 正常）
Shizuku.newProcess(arrayOf("pm", "uninstall", "-k", "--user", "0", pkg), "", false)

// 还原
Shizuku.newProcess(arrayOf("cmd", "package", "install-existing", pkg), "", false)
```

**权限状态机（单一真源，UI 订阅）**

```kotlin
enum class Capability { LIST_ALL, UNINSTALL, USAGE_STATS, SHIZUKU }

// 每个能力一个判定器，UI 不再自行 if 判断权限
val capabilityFlow: Flow<Set<Capability>> = flow {
    emit(buildSet {
        if (pm.isPermissionGranted(QUERY_ALL_PACKAGES)) add(Capability.LIST_ALL)
        if (usageStatsGranted()) add(Capability.USAGE_STATS)
        if (shizukuState == READY) add(Capability.SHIZUKU)
    })
}
```

## 8. 风险与对策

| 风险 | 概率 | 影响 | 对策 |
|---|---|---|---|
| `QUERY_ALL_PACKAGES` 政策收紧 | 中 | 高（无法上架 Play） | 主渠道 GitHub/F-Droid；Play 仅作备选，准备 `<queries>` 白名单降级模式 |
| Shizuku 被 ROM 厂商限制 | 中 | 中（系统应用治理不可用） | 三态明确提示 + 降级到「仅停用」；文档给出各 ROM 适配说明 |
| ROM 存储统计 API 行为差异 | 高 | 中（数值对不上系统设置） | 统一封装 + 60s 缓存 + 文档标注误差范围；不追求与系统设置完全一致 |
| 精确使用时长需授权且部分 ROM 不返回 | 高 | 中（排行数据缺失） | 显式「无数据」状态；用最后使用时间作为主判据，时长为辅助 |
| split APK 备份无法原位覆盖安装 | 高 | 中（用户预期落空） | 备份页明确文案说明「用于无此应用环境重装」；给出 `adb install-multiple` 命令 |
| 批量操作误触导致数据丢失 | 中 | 高 | 风险分级 + 关键应用硬禁用 + 二次确认 + 审计日志 + 撤销 + 备份前置 |
| 图标缓存 OOM | 中 | 中 | LRU 上限 + 按需降采样到 96px + 内存压力回调清理 |
| 敏感权限被误判 | 中 | 中 | 规则来自公开知识库且用户可编辑/关闭单条规则，不做「一票否决」 |

## 9. 分发与运营

- **渠道**：GitHub Releases（主）+ F-Droid（备）+ 官网直链。
- **版本策略**：语义化 `MAJOR.MINOR.PATCH` + 四位构建号（如 `2.0.0.001`），与一代保持一致；`versionCode` 单调递增。
- **Release 产物**：已签名 APK + 源码 tag + 变更说明 + 校验哈希。
- **更新提示**：应用内检查版本（仅在用户主动点击「检查更新」时触发，且需用户授权网络——**二代首次引入可选网络权限，默认关闭**）。

> 说明：一代坚持「无网络权限」。二代为保留核心的纯离线承诺，更新检查设计为**可选且默认关闭**，用户显式开启后才在 Manifest 生效该能力；未开启时不做任何网络请求。

## 10. 假设与未验证项（如实声明）

1. 本方案基于 Android 官方文档与主流开源项目（Canta / UAD / App Manager）的公开资料撰写，**未在真机上逐项验证**，各 ROM 的实际行为需在 V2.0.0-alpha 阶段实测校准。
2. 风险分级规则的具体清单需要按目标用户机型做统计与校准，二代先以内置规则文件交付，规则可由用户编辑。
3. Shizuku 的 `pm uninstall -k --user 0` 在部分厂商 ROM 上可能被拦截或改写行为，V2.0.0 前必须完成 4 台真机验证。
4. `getAppBytesByDataType` 仅 Android 15+，低版本分项粒度较粗，UI 需按版本条件渲染。
5. 小组件与浮窗涉及厂商后台限制（尤其国内 ROM 的自启与省电策略），可能需引导用户加白名单。
