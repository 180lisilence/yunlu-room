# 手机应用管理器 — 初版方案（V0.1）

> 调研来源：GitHub 开源项目 + Android 官方 API 文档 + Shizuku 官方文档
> 调研日期：2026-10-13
> 文档状态：初版方案，待评审后进入技术设计

---

## 1. 项目概述

### 1.1 目标

做一个运行在手机上的应用管理 App，核心能力：**查看本机已安装应用**（列表、详情、占用、权限）与**卸载应用**（单个/批量），并在此基础上逐步扩展存储清理、使用统计、系统应用管理等能力。

### 1.2 定位

- 面向「想搞清楚手机里装了什么、把不用的应用清掉」的普通用户 + 进阶玩家。
- 单机工具，**不联网、不采集、不上传**任何数据（对标 App Manager 的做法：无网络权限）。
- 分发走自有渠道 / GitHub Releases / F-Droid，不上 Google Play（原因见 8.3 权限政策）。

### 1.3 非目标（初版明确不做）

- 不做应用商店/APK 下载市场（那是另一条产品线，apkgit 方向）。
- 不做 iOS 版本（沙盒机制不可行，见 2.3）。
- 不做云同步/账号体系。

### 2.2 从标杆项目提炼的 8 条经验

1. **能力分层，按设备权限灰度解锁。** App Manager 把功能明确切成三档：普通功能（列表/详情/装卸/备份）、Root 或 ADB 功能（强制停止/清数据/冻结/权限管理）、Root-only 功能（block 组件/SSAID）。初版照搬这个模型，避免「没 root 的用户一打开全是灰的」。
2. **详情页信息要全。** App Manager 详情页列出：activities、broadcast receivers、services、providers、app ops、permissions、签名、共享库、manifest、tracker 扫描。初版先做「基础信息 + 权限列表 + 存储占用」，其余排期。
3. **卸载必须走系统 Intent + 用户确认。** 无 root 时卸载 = `Intent.ACTION_DELETE`（或 `ACTION_UNINSTALL_PACKAGE` + `EXTRA_RETURN_RESULT` 拿回调），系统弹窗由用户确认。这是合规且唯一稳定的路径。
4. **批量操作是核心体验。** 批量卸载、批量备份、批量分享。「多选模式 + 底部操作栏」是标配。
5. **用户应用 / 系统应用分组。** 列表默认只显示用户应用，系统应用折叠到独立 tab 并加风险标识（App Manager、BharathVishal 均如此）。
6. **Android 11+ 必须处理包可见性。** `QUERY_ALL_PACKAGES` 权限 + `<queries>` 声明；Google Play 对该权限有审核政策，是分发渠道选 F-Droid/GitHub 的直接原因。
7. **监听安装/卸载事件实时刷新列表。** 通过 `PackageManager` 的 `ACTION_PACKAGE_ADDED/REMOVED/REPLACED` 广播 + 重新查询，而不是每次手动刷新。
8. **进阶能力走 Shizuku 而非强依赖 root。** Shizuku 用 ADB/root 启动一个 server，让普通应用以 shell 级权限调用系统 API（`pm uninstall --user 0`、`pm disable`、`pm clear`、`grantRuntimePermission` 等）。覆盖没有 root 的进阶用户，且比 `Runtime.exec("pm ...")` 快且稳（后者每次 fork 进程、解析文本，不可靠）。

### 2.3 平台可行性结论：只做 Android

- **iOS 不可行**：所有第三方 App 强制沙盒，公开 API 无法枚举/卸载其他应用。企业场景只有 MDM（描述文件推送，需 Apple Business Manager + MDM 服务器）；个人场景只有越狱（Cydia/dpkg）或桌面工具（iMazing）。做不了「手机上的手机应用管理器」这个形态。
- **Android 可行且成熟**：公开 API 覆盖查看与用户应用卸载；Shizuku/Root 覆盖系统应用管理与深度操作。

## 3. 技术选型

| 维度 | 选择 | 理由 |
|---|---|---|
| 平台 | Android only（minSdk 24，targetSdk 35） | 见 2.3；minSdk 24 覆盖约 98% 活跃设备，同时避开 6.0 以下的远古权限模型 |
| 语言 | Kotlin | 官方首选，Shizuku/各类系统 API 库均为 Kotlin/Java 生态 |
| UI | Jetpack Compose + Material 3（动态取色） | BharathVishal 轻量版与 Device Storage Manager 均验证可行；开发效率高 |
| 架构 | MVVM：Compose UI → ViewModel(StateFlow) → Repository → 系统 API | 单机工具最简结构，无过度设计 |
| 异步 | Kotlin Coroutines + Flow | 应用列表查询/卸载结果均为异步回调，天然匹配 |
| DI | Hilt | 模块化后管理 Shizuku/Root 多实现注入 |
| 存储 | Room（仅缓存列表快照与操作历史） | 避免每次冷启动都全量查询 PackageManager |
| 图标/图片 | 直接用 `PackageManager` 返回的 Drawable 转 Bitmap | 不落盘、不复制 APK |

**不选 Flutter 的理由**：device_apps 插件能完成 80% 列表/查看，但 Shizuku、hidden API、`PackageInstaller` 会话等深层操作仍需写原生 Platform Channel，混合工程复杂度反而更高；且本工具重度依赖 Android 系统 API 细节，原生 Kotlin 调试链路最短。

## 5. 权限与能力分层模型（核心设计）

直接复用 App Manager 的分层思想，落到本项目的 6 层：

| 层级 | 获取方式 | 解锁能力 |
|---|---|---|
| L0 基础 | 安装即有 | 应用列表（含 launcher 应用）、详情查看（公开字段）、启动应用 |
| L1 全量列表 | `QUERY_ALL_PACKAGES`（Android 11+ 普通权限，安装即授） | 看到全部已安装应用，而非只有带 launcher 的 |
| L2 卸载用户应用 | `REQUEST_DELETE_PACKAGES` + `ACTION_DELETE` Intent | 卸载/批量卸载（系统弹窗确认） |
| L3 使用数据 | Usage Access（`PACKAGE_USAGE_STATS`，需跳系统设置手动开启） | 使用时长、打开次数 |
| L4 Shizuku | 用户安装并授权 Shizuku（无线 ADB 或 root 启动） | 卸载当前用户的系统应用、禁用/冻结、强制停止、清缓存、管理其他应用权限 |
| L5 Root | Magisk/KernelSU 授权 | 全部 L4 能力 + 组件 block、系统配置查看/修改（对标 App Manager root-only 档） |

**设计原则**：
- 每一层在 UI 上都是「渐进解锁」：没有对应权限的功能显示为「需开启 XXX」，点击后引导到对应授权路径，绝不静默失败。
- 卸载系统应用在 V1.0 前一律隐藏入口（L4 解锁后才显示），并对「卸载当前用户（可恢复）」与「彻底删除」做明显区分——前者通过 `pm uninstall -k --user 0` 实现，重启/恢复出厂可找回；后者有变砖风险，默认不提供。
- 危险操作（批量卸载 > 5 个、卸载系统应用）二次确认弹窗，列出全部目标包名。

## 6. 系统架构

### 6.1 模块划分

```
app/                        # Application 入口、导航、DI 装配
core-model/                 # 数据模型（AppInfo, AppPermission, StorageInfo...）
core-common/                # 工具（格式化、扩展函数、Result 包装）
data-package/               # PackageManager 封装：AppRepository（列表/详情/卸载/广播）
data-storage/               # 存储统计（反射 GET_PACKAGE_SIZE 或 StorageStatsManager）
data-usage/                 # UsageStatsManager 封装
data-shizuku/               # Shizuku 适配层（接口 + Shizuku 实现）
data-root/                  # Root 适配层（接口 + su 实现，V1.0）
feature-applist/            # 列表页（Compose）
feature-appdetail/          # 详情页（Compose）
feature-batch/              # 多选/批量操作
```

### 6.2 关键数据流

```
列表加载：AppListViewModel → AppRepository.getApps(filters)
         → PackageManager.getInstalledApplications(GET_META_DATA)
         → Flow<List<AppInfo>> → UI

实时刷新：系统广播 PACKAGE_ADDED/REMOVED/REPLACED
         → AppRepository.appListInvalidator（MutableSharedFlow）
         → ViewModel 重新查询

卸载（L2）：UninstallUseCase
         → Intent(ACTION_DELETE, Uri.parse("package:$pkg"))
         → startActivityForResult → RESULT_OK / CANCELED 回传
         → 更新 Room 操作历史
```

### 6.3 多实现权限后端（L4/L5）

```kotlin
interface PrivilegedBackend {
    val isAvailable: Boolean
    suspend fun uninstallForUser(pkg: String, userId: Int = 0): Result<Unit>
    suspend fun setAppEnabled(pkg: String, enabled: Boolean): Result<Unit>
    suspend fun forceStop(pkg: String): Result<Unit>
    suspend fun clearCache(pkg: String): Result<Unit>
}

// V0.1: NoOpPrivilegedBackend（isAvailable = false，UI 显示引导卡片）
// V1.0: ShizukuPrivilegedBackend / RootPrivilegedBackend
```

## 8. 关键技术实现要点（V0.1 代码级）

### 8.1 全量应用列表（Android 11+）

`AndroidManifest.xml`：
```xml
<uses-permission android:name="android.permission.QUERY_ALL_PACKAGES" />
<uses-permission android:name="android.permission.REQUEST_DELETE_PACKAGES" />
```

```kotlin
suspend fun loadApps(): List<AppInfo> = withContext(Dispatchers.IO) {
    val flags = PackageManager.GET_META_DATA
    packageManager.getInstalledApplications(flags).map { ai ->
        val pi = packageManager.getPackageInfo(ai.packageName, 0)
        AppInfo(
            pkg = ai.packageName,
            name = packageManager.getApplicationLabel(ai).toString(),
            icon = packageManager.getApplicationIcon(ai),
            versionName = pi.versionName ?: "-",
            isSystemApp = ai.flags and ApplicationInfo.FLAG_SYSTEM != 0,
            firstInstallTime = pi.firstInstallTime,
            lastUpdateTime = pi.lastUpdateTime,
        )
    }.sortedBy { it.name.lowercase() }
}
```

### 8.2 卸载（含结果回调）

```kotlin
// 注册：registerForActivityResult(ActivityResultContracts.StartActivityForResult())
val intent = Intent(Intent.ACTION_UNINSTALL_PACKAGE).apply {
    data = Uri.parse("package:$pkg")
    putExtra(Intent.EXTRA_RETURN_RESULT, true)   // API 14+ 拿结果
}
launcher.launch(intent)

// 回调：resultCode == RESULT_OK 成功；RESULT_CANCELED 用户取消；RESULT_FIRST_USER 失败
```

### 8.3 实时刷新

```kotlin
// 广播：ACTION_PACKAGE_ADDED / ACTION_PACKAGE_REMOVED / ACTION_PACKAGE_REPLACED
// 注意 scheme：intent.data = Uri.parse("package:$pkg")
registerReceiver(object : BroadcastReceiver() {
    override fun onReceive(c: Context?, i: Intent?) {
        when (i?.action) {
            ACTION_PACKAGE_ADDED, ACTION_PACKAGE_REMOVED, ACTION_PACKAGE_REPLACED ->
                appListInvalidator.tryEmit(Unit)
        }
    }
}, IntentFilter().apply {
    addAction(Intent.ACTION_PACKAGE_ADDED)
    addAction(Intent.ACTION_PACKAGE_REMOVED)
    addAction(Intent.ACTION_PACKAGE_REPLACED)
    addDataScheme("package")
})
```

### 8.4 存储占用（V0.2）

- `StorageStatsManager.queryStatsForPackage(uuid, pkg, UserHandle)`（API 26+，需 `PACKAGE_USAGE_STATS` 或系统签名）
- 旧版本反射 `PackageManager.getPackageSizeInfo`（`GET_PACKAGE_SIZE` 隐藏 API，App Manager 有 hiddenapi 模块封装）

### 8.5 Shizuku（V1.0）

- 依赖 `moe.shizuku:api` + `rikka.shizuku:provider`，hidden API 受限的 Android 9+ 配 `AndroidHiddenApiBypass`
- 核心调用：`IPackageManager.Stub.asInterface(ShizukuBinderWrapper(SystemServiceHelper.getSystemService("package")))` → `deletePackageAsUser` / `setApplicationEnabledSetting`
- 注意 Shizuku 重启后需重新申请权限（`Shizuku.addRequestPermissionResultListener`）

## 9. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| Google Play 拒绝 `QUERY_ALL_PACKAGES` | 上架受阻 | 不上 Play；GitHub Releases + F-Droid + 官网；声明用途说明（package manager 属豁免场景） |
| 卸载系统应用导致设备异常 | 用户投诉/变砖 | 系统 tab 默认只提供「针对当前用户卸载」（`--user 0` 可恢复），彻底删除入口默认隐藏 |
| 国产 ROM 定制限制（MIUI/ColorOS 对 Shizuku/广播的限制） | 功能在部分机型失效 | 机型兼容矩阵测试；优雅降级提示 |
| 隐藏 API 在 Android 高版本失效 | 存储/包大小功能异常 | 优先公开 API（StorageStatsManager），反射做兜底并 try-catch |
| 批量卸载体验割裂（每个包一次系统弹窗） | 体验差 | V1.0 提供 Shizuku/Device Owner 静默通道；V0.1 在二次确认页明确告知「将逐项确认」 |
| 应用数量多时列表卡顿 | 性能 | 列表数据一次查询缓存进 Room，增量刷新靠广播；图标 Glide 式异步 |

## 11. 假设清单

1. 目标平台为 Android，iOS 不在本方案范围（依据调研结论 2.3）。
2. 「管理手机应用的手机软件」指设备本地管理工具，不含 PC 端/Web 端（PC 端 ADB 方案 saliholoji 项目已验证可作后续延伸）。
3. 初版不接任何网络请求，全部本地能力；分发以 GitHub Releases / F-Droid 为主。
4. 团队具备 Android 原生开发能力（Kotlin + Compose），无跨平台历史包袱。
5. minSdk 24 起；测试机至少覆盖一台 Android 11+（包可见性）与一台无 root 但可装 Shizuku 的机型。
